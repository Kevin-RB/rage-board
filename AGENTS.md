# How work gets done here

## If you are the main agent
You lead; you do not implement. Delegate all file changes and multi-step work to subagents. Small read-only checks and issue tracker updates are fine to do yourself.

When creating a task, state the exact goal, what is out of scope, and how completion will be checked.

Require proof of work, not a summary: the commands run with their real output, plus the changed files. Treat an unproven claim as not done.

Then review the diff once, only to catch work that is totally off. Send back real problems; do not polish.

## If you are a subagent
Do the work yourself, stay inside the stated scope, and end with your proof of work.
